# Upgrading to 2.5.8

Version 2.5.8 needs no migration. Saved layouts, drawings and workspace documents
from 2.5.7 load unchanged, no export was added or removed, and a chart that keeps
the default zoom floor paints the same pixels. It changes one default and how a
study writes its plots, and it makes several internal paths cheaper that a test
of your own may count.

Check these points in your host:

- **Level of detail (`conflate`) is on by default.** It engages only below about
  one CSS px per bar, which the default `timeScale.minBarSpacing: 1` never reaches.
  If your host lowers `minBarSpacing`, a chart zoomed out past that spacing now
  draws one OHLC-preserving stick per device-pixel column, and line and histogram
  series keep each column's extremes. OHLC bar series look thinner there, because
  one stick's open and close ticks spill into fewer neighbouring columns than every
  bar's did; the envelope is the same. Refresh screenshot baselines taken at those
  zoom levels, or pass `conflate: false` to draw every bar. See
  [Large datasets](/docs/data-loading#large-datasets-level-of-detail).
- **`conflationFactor` has a new meaning.** It is now the column width in sticks;
  it used to multiply a half-pixel threshold. A value you set therefore engages the
  merge at a wider spacing than before. A chart type you registered with
  `registerChartType`, even under a built-in name, still receives every bar.
- **A custom `IndicatorHost`** (only if you implement it yourself; `createChart`
  supplies its own). On a live tick a study now writes its plots through `update`
  on the series your `addIndicatorSeries` returned, for the points that changed and
  the last point, instead of one `setData` of the whole history. That series'
  `update` must behave as `SeriesApi.update` documents: an item at an existing time
  replaces that point, an older one included, and a newer one appends. A series
  that ignores `update` shows the study frozen at its last whole write.
- **Data written into a study's plot.** `indicator.series(key)` is for styling. Data
  you write into it used to be overwritten on the next recompute; it now survives
  wherever the study did not move a point. Put values of your own on a series of
  your own.
- **Primitive hit boxes (`hitBounds`).** Optional: a primitive without one is asked
  on every pointer move as before. If you add one, it must hold every point your
  `hitTest` answers, work from the same geometry `hitTest` uses, and change only
  with the scales, the pane's layout, hover and drag, or your own state announced
  through `host.requestUpdate()`; anything else it depends on (bar prices, say)
  must call `requestUpdate` when it changes. A primitive that declares a box is
  attached with a host object that wraps the chart's, so do not compare that host
  with another by identity. See [Hit boxes](/docs/primitives-and-plugins#hit-boxes).
- **`hitTest` can be skipped.** Besides the boxes, a pointer move stops at an exact
  hit (`distance: 0`) among the primitives painted in front. Keep `hitTest` free of
  side effects, and never return a negative `distance`.
- **Draw items are reused.** The `items` array and its objects handed to a
  `RendererEntry.draw` or an `IRenderBackend.drawSeries` are rewritten the next time
  the pane draws that series. A renderer or backend that keeps them past the call
  must copy them.
- **The built-ins' `calcTail`.** Sixteen built-ins now carry one, as a property that
  is not enumerable, so `{ ...getIndicator('ema'), calc: myCalc }` recomputes in
  full through `myCalc` as before. Code that lists a built-in's keys sees no change;
  code that tests `descriptor.calcTail` on one of the sixteen now finds a function.
  Copy it by name (`calcTail: getIndicator('ema').calcTail`) only when your `calc`
  returns the built-in's result unchanged. See
  [the built-ins' tails](/docs/indicators#the-built-ins-tails-258).
- **Glides step inside the chart's frame.** An injected `raf` now gets one request
  per kinetic or zoom-glide frame instead of two, a glide's `pan` and `zoom` events
  fire in the frame that paints them, and the autoscale easing during a glide starts
  a frame earlier. Charts in a `LinkGroup` paint a glide one frame apart: the leader
  in the frame it steps, a follower in the next, where both used to lag a frame
  together. A history loader that throws while a glide runs now also skips that
  frame's paint until the next change; catch inside the loader.
- **Fewer repaints.** A tick that replaces the forming bar, and a study recompute,
  no longer repaint the panes they do not change, so a test counting
  `Pane.paintBase` calls sees fewer. The pixels are those of a full repaint. While
  the bar countdown is on, every pane with a price series still repaints on each
  tick, and the bottom pane while the corner clock is on.

New and optional: `IPrimitive.hitBounds`. See
[Primitives and plugins](/docs/primitives-and-plugins),
[Indicators](/docs/indicators) and the
[release notes](/docs/release-notes#258).

## Earlier upgrades

Version 2.5.7 needed no migration and no code change. It reorganised the chart's
internal code; every public method, option, event and type stayed the same, saved
layouts, drawings and workspace documents from 2.5.6 loaded unchanged, and charts
painted the same pixels. The base engine grew by 1.52 kB Brotli. Code that reached
into the chart's private members (never supported) found several of them moved to
internal collaborators.

Version 2.5.6 needed no migration. Saved layouts, drawings and workspace
documents from 2.5.5 loaded unchanged, and every new contract was optional.

Check these points in your host:

- Times past the last bar now continue at the median of the last 64 bar
  intervals, or follow a session calendar when you set one, instead of the gap
  between the last two bars. Stored drawings keep their times; one anchored in
  the future is drawn where that time now falls. Evenly spaced data maps
  exactly as before.
- Pane boundaries round to whole device pixels. At a ratio of 1 a pane's height
  can differ from its exact share by up to one pixel, and at a fractional ratio
  the separator is a one device pixel box over the lower pane instead of a CSS
  border. Screenshot baselines of multi-pane charts at 1.25 or 1.5 need
  refreshing; at whole-number ratios a chart whose pane heights are whole
  pixels paints exactly as before.
- Chrome icons draw a 2px line and 19 drawing tool glyphs changed. Update any
  snapshot of the icon markup.
- `indicator.setSettings` and `indicator.remove` return a boolean, false when a
  study policy refuses the call. User-facing controls you build should call
  them without `{ force: true }`, so a policy the host set is respected.
- The OpenAlgo adapters and `FakeDataFeed` refuse a non-default data variant
  with `DataVariantUnsupportedError`. A feed without `dataVariants` serves only
  its default series.
- A variant-only change through `publishDataContext` emits `data:context` twice,
  a passing context with the interval cleared and then the real one. A host
  listener that fetches on `data:context` should skip a context without an
  interval.
- The widget's Undo and Redo now walk `widget.history`, not only the drawing
  history. A host with its own undo stack can read `DrawingController.historySteps()`
  and the `step` on `drawing:change`, or hand input anchor steps over with
  `delegateInputAnchorSteps`.
- A host that types a complete translation dictionary as
  `Record<WidgetBuiltinMessage, string>` must add the new messages for
  conditional inputs, point picks, data variants, protected studies and undo
  failures; a translator that returns `undefined` keeps the English text.
- Deprecated, working until 3.0.0: `mapOrder`, a study level's `dashed`, the
  flat modifier flags on `click`, `chart.movePriceAxis` and the `depth_level`
  key in depth frames. See the [compatibility policy](/docs/compatibility).

New and optional: `IndicatorPolicy` on `addIndicator`, the series stack
(`seriesStack`, `moveInSeriesStack`, `placeInStack`), `ChartHistory`, data
variants (`BarsRequest.variant`, `DataFeed.dataVariants`, the widget's
`variant` option), `SessionCalendar` and `chart.setSessionCalendar`, paired
`timeKey` inputs with `chart.beginPick('point')`, `visibleWhen`, `activeWhen`
and `inline` on inputs, and background targets. See
[Indicators](/docs/indicators), [Data variants](/docs/data-variants),
[Instruments](/docs/instruments), [Scales and panes](/docs/scales-and-panes) and
[Widget controls](/docs/widget).

Version 2.5.5 needed no migration. Saved layouts, drawings and workspace
documents from 2.5.4 loaded unchanged, and every new contract was optional.

Check these points in your host:

- Moving the price pane is off unless you opt in with `movablePrimaryPane` on
  `createChart`, `createWidget` or `createChartGrid`. Without it pane 0 is the
  price pane exactly as before. Before you opt in, replace every explicit `0`
  that means the price pane with no pane argument or `chart.primaryPaneIndex()`,
  follow `paneMoved`, and include `primaryPane` in any saved-state allowlist.
  See [Opting in](/docs/scales-and-panes#opting-in).
- A chart state that moved the price pane is written as version 2, and an older
  engine refuses it rather than misplacing the price pane.
- Running studies such as ATR, Supertrend, VWAP, OBV, A/D, Parabolic SAR, CCI,
  Stochastic, RVI and TSI now resume after a missing or non-finite input
  instead of going blank. Complete data reads as before, apart from last-digit
  changes in TEMA, Stochastic, True Strength Index and the SMI Ergodic pair,
  and the corrected Trend Strength Index. See the
  [release notes](/docs/release-notes#255) and the Numerical contract section of
  [Indicators](/docs/indicators).
- `OpenAlgoTradeFeed.place` refuses `account`, `duration`, `expiresAt` and
  `leverage`, which OpenAlgo's order endpoint does not take, before any request.
- A host that types a complete translation dictionary as
  `Record<WidgetBuiltinMessage, string>` must add the new account summary, pane
  move and drawing anchor messages; a translator that returns `undefined` keeps
  the English text.

Also new then: named watchlists (`WatchlistRepository`) with `QuoteFeed`
rows and a `NewsFeed` reader in the widget dock, account state and native
position commands for brokers that declare them (`AccountManager`,
`TradingFeatures`, `previewOrder`, `closePosition`, `reversePosition`),
price-dependent `TickSchedule` bands, and drawings pinned to the viewport
(`space: 'viewport'`). See [Widget controls](/docs/widget), [Trading](/docs/trading),
[Instruments](/docs/instruments) and [Drawing tools](/docs/drawing-tools).

Version 2.5.4 needed no migration. Saved layouts, drawing documents and workspace
documents from 2.5.3 load unchanged; pane `collapsed`, drawing `policy` and a
pane's `historyPeriod` are optional fields that older records simply omit.

Check these points in your host:

- `chart.navigationOptions()` now also reports `panEnabled` and `zoomEnabled`.
  A test or a comparison that expects exactly `{ mousePan, defaultVisibleBars }`
  must include them, or compare the fields it cares about.
- When studies are applied, the top visible pane's legend starts with the
  persistent **Indicators N** control, so study rows begin one row lower. Code
  that locates legend rows by fixed pixel offsets must allow for that row.
- An external-data study requests its values again after the chart's history
  is resynchronised, because the bars are a new source revision. Resolve that
  request as you would the first; its status reads as loading until you do.
- The widget's top bar gains **Go to**. A host that types a complete translation
  dictionary as `Record<WidgetBuiltinMessage, string>` must add the new go-to and
  grid messages; a translator that returns `undefined` keeps the English text.
- HMA at odd lengths and the early ADX readings follow corrected definitions, and
  several averages treat missing or overflowing inputs as unavailable. Strategies
  tuned on the old values should be checked. See the
  [release notes](/docs/release-notes#254).

New and optional: `widget.goTo()` and `DateNavigator` for date navigation,
`createChartGrid` for a grid of widgets, `chart.setPaneCollapsed()`, `overlay`
and `plot` targets on study drawings and markers, and a `policy` on drawings.
A drawing UI of your own should route its edits through the drawing controller,
which enforces policies, and pass `{ force: true }` only for the host's own
changes. See [Chart grid](/docs/chart-grid), [Data loading](/docs/data-loading),
[Scales and panes](/docs/scales-and-panes) and [Drawing tools](/docs/drawing-tools).

Version 2.5.3 adds the widget's Data and Objects dock, richer symbol lookup,
direct typing, shared colour controls, and individual running-study removal.
The dock starts closed. Set `panels: false` to retain the Objects popup, and
`typingNavigation: false` when your application already owns plain typing.
Existing symbol lookup callbacks and results still work. Asset categories,
images, and futures contracts are optional host-provided metadata.

Saved widget records can include `panels`, and drawing documents can include
named `groups`. Older records load without migration. Study movement retains IDs
and attached alerts. Reordering changes the rendered order; custom object
providers can opt into the new `move` and `reorder` callbacks. Custom inventories
should handle the additive `group` object kind when consuming grouped drawings.
If your TypeScript host uses `Record<ChartObjectKind, ...>` or an exhaustive switch,
add a `group` entry before upgrading. Existing stored drawings do not need a rewrite.

For custom hosts, `createAlertUi().context` can mount the shared panel, search,
and form components. Use the context's overlay opener for nested colour popups,
and call a generated form's `destroy()` before unmounting it. Include
`WIDGET_COMPONENT_CSS` alongside `WIDGET_CSS` if your host manages styles.
See [Widget controls](/docs/widget) and [Objects](/docs/objects).

Version 2.5.2 adds Anchored VWAP and Fixed Range Volume Profile to the drawing
registry. Existing drawing records still load. Both tools need candle volume;
missing observations stay missing, and a profile is a candle-based estimate,
not a record of traded volume at each price. See [Drawing tools](/docs/drawing-tools).
Custom toolbars with a fixed tool list must add `anchored-vwap` and
`fixed-range-volume-profile` to expose them. The widget and reference host already do.

Drawing and appearance synchronization are opt-in. Use `DrawingLinkGroup` from
`openalgo-charts/draw` for price-pane drawings on the same symbol and exchange.
Persist its drawing metadata to reconnect saved copies, and call `share()` to
include existing local drawings. Appearance links use the chart settings adapter;
they do not copy instrument, timezone, alerts or orders. See [Chart linking](/docs/chart-linking).

Timeline events retain their existing marker behavior. Enable clustering and
groups through the new event APIs. The widget opens plain-text event details by
default; set `eventDetails: false` if your host supplies its own popup. Calendar
data and optional detail loading remain the host's responsibility. See
[Timeline events](/docs/events) and the [2.5.2 release notes](/docs/release-notes#252).
Set the new instrument context before supplying its events: symbol or exchange
changes clear the previous calendar, while interval changes preserve it.

Version 2.5.1 adds the opt-in controller setting `spentLines: 'hide'` to hide
triggered and expired alert lines. The default remains `'show'`. The alert stays
in `list()` and saved state, so a once-only alert remains spent after reload.
Re-arming restores its line. Set this policy when constructing each controller;
it is not stored in alert documents. See [Finished alert lines](/docs/alerts#finished-alert-lines).

Version 2.5.0 adds automatic table columns with `cellWidth: 'auto'` and clips text
inside every cell. Alert drags now snap to their source scale's tick in both
preview and release. The widget and yfinance host support removing a hovered
alert with Delete or Backspace, after drawing and text-editing shortcuts. Custom
hosts can use `alerts.hovered()` to add the same shortcut.

Version 2.5.0 keeps fixed price-alert levels visible across timeframes for the
same symbol and exchange. The label names the original timeframe and an armed
alert shows Paused when another timeframe is open. Evaluation still uses the
original timeframe, including intrabar alerts. Return to that timeframe to
resume; the controller does not evaluate unseen bars in the background.
Triggered records survive reload, and changing intervals cannot consume another
interval's evaluated-bar checkpoint. No API or saved-alert migration is needed.
See [Trader alerts](/docs/alerts#switching-timeframes) and the
[2.5.0 release notes](/docs/release-notes#250).

Version 2.4.8 shows a grabbing hand while you hold the plot. Mouse and pen panning
stops on release, including a release outside the chart. Touch flicks keep their
momentum. Two-axis panning remains the default; saved horizontal-only preferences
still apply. No API or saved-state migration is required. See the
[2.4.8 release notes](/docs/release-notes#248).

Price and study-threshold alerts now support dragging through the existing alert
controller. No additional drag callback is required. Preview only moves the line;
`alert:updated` and saved state change once on release. Cancel with Escape or a
touch cancellation. Pause, replay, source changes and restoring or updating an
alert discard an unfinished gesture. Drawing-anchored levels still move with
their drawing. An armed badge reads "Alert"; persisted state is still `armed`.

If your host consumes raw primitive gestures, `drag:start` uses the same payload
shape as `drag:end`. `drag:cancel` carries `{ id, paneIndex, reason }`, with reason
`pointercancel`, `pinch` or `escape`. For compatibility, pointer cancellation
still delivers the existing end notification after cancellation; discard your
draft on `drag:cancel` before considering a later release. Custom primitives
opt into Escape rollback with `PrimitiveHit.cancelOnEscape: true` and must
handle cancellation without requiring an end notification.

See [Trader alerts](/docs/alerts), the [alert example](/examples#alert-threshold-dragging) and
[2.4.7 release notes](/docs/release-notes#247).

## Existing 2.4.6 integrations

Version 2.4.6 preserves default plot anchoring. To place an overlay's signals
outside candle highs and lows, set `markerAnchor: 'price'` on its descriptor.
This uses the primary series and its current price scale. Separate-pane studies
keep their own plot anchors. Instrument bars fill plot gaps only when the plot
and primary series share the price scale.

Set `hasSource: true` only when your host handles `indicatorSource`. The event
identifies the descriptor, instance and pane; your host resolves and displays
the source. Use `legendIconSize` or `chart.setLegendIconSize()` to set a common
button size across existing and future legend rows. See the
[indicator guide](/docs/indicators) and [release notes](/docs/release-notes#246).

The 2.4.6 alert editor uses its opening chart timezone for expiry and prefills
new drafts two calendar months ahead. Clearing the field keeps an alert
indefinite. Existing saved alerts and programmatic defaults are unchanged.
Hosts with translation catalogs should add the new zone-neutral expiry
messages; previous typed keys remain accepted. Dialog fields also respect
`--oac-ctl-h` and `--oac-radius` and share a consistent control column.

## Adopting the 2.4.5 host contracts

Existing chart options keep their defaults. Update the package and lockfile,
then run your host's source-switch, persistence, replay and trading guard checks.
The optional APIs require explicit host wiring; a dependency update alone does
not add workspace controls to an existing terminal.

- Import [named layout and template contracts](/docs/workspaces) from `openalgo-charts/workspace`.
  Keep account namespaces separate and show rejected saves or revision conflicts.
  Portable documents exclude credentials, live orders, positions and armed state.
- Treat [open interest](/docs/open-interest) (`Bar.oi`) as a level: folds take the latest defined reading, never a sum.
  Preserve missing observations and real zero separately. Declare instrument OI
  support independently of whether the current bar has an observation.
- Restore drawing and study identities before their alerts. Triggered once alerts
  survive reloads, and restoration sends no historical notifications. Alert
  delivery remains your host's responsibility.
- Use [Instrument](/docs/instruments) for validated calendar, supported interval,
  formatting and quantity rules. Keep request cancellation and quantity units at
  your adapter boundary.
- Supply optional [widget translation and trading capabilities](/docs/widget)
  when needed. Capability checks complement server authorization and broker
  authority. Keep order entry locked through replay selection and transitions,
  as well as active or paused replay.

The [complete integration guide](https://github.com/marketcalls/openalgo-charts/blob/master/docs/upgrading-to-2.4.5.md)
includes data, persistence and validation details. Read the
[compatibility policy](/docs/compatibility) for public API and support boundaries,
and the [release notes](/docs/release-notes#245) for the full change list.
