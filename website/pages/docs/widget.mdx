# The widget tier

`openalgo-charts/widget` turns the engine into a working terminal in one call: a chart
with a top bar (symbol, interval, chart type, theme, settings, indicators, objects, alerts), a drawing rail
down the left, a status line, the dialogs behind each of those buttons, keyboard shortcuts
with a `?` panel that lists them, and optional persistence of the layout. It is one of nine
loadable tiers (**82.66 kB** Brotli in the current build) and the only tier that supplies
application controls.

The drawing rail includes Anchored VWAP and fixed-range Volume Profile. They use
the chart's OHLCV data, participate in normal drawing edits and undo, and expose
their settings through drawing properties. See [Drawing Tools](/docs/drawing-tools).

The **Capture** menu offers **Download chart data (CSV)** alongside image export.
CSV contains loaded OHLC, volume, OI, configured study plots and aligned comparison
closes. Missing readings stay blank; time is UTC seconds. During replay, only the
revealed data is exported. Loading or changing the source requires reopening the
menu after the chart is ready. Applications with their own controls can call
`exportChartDataCsv(chart)` from the base package and deliver the returned text as
`text/csv;charset=utf-8`.

## Engine and interface separation

`openalgo-charts` and the seven non-widget optional tiers contain no toolbar, no dialog, no
menu and no stylesheet. The engine creates canvas and container elements; it does not provide application controls. The widget is
a host, packaged: everything it draws in HTML it drives through the same public API a host
of your own would use (`createChart`, `DrawingController`, `chartSettingsSchema`, the
`contextmenu` event, the indicator registry).

That promise is enforced, not stated:

- **The tier ACL** (`eslint.config.js`). Nothing under `src/` except `src/widget/` may
  import the widget, and the widget may reach the engine and the draw tier only through
  their package specifiers, so it can never be inlined into another bundle.
- **`npm run shake`** bundles an entry that imports only `createChart` and asserts the
  widget's CSS scope (`oac-widget`) is absent from the result, on every build.
- **The size budgets** (`.size-limit.json`). The base engine row did not move when the
  widget arrived; the widget has its own row, and a `Widget terminal` row measures what
  one `createWidget` call actually loads.

Importing the module touches no DOM either; only `createWidget` does. The module can
therefore be imported by code that also runs on a server, and called once a container
exists.

## Data and Objects panels

From 2.5.3, **Data** and **Objects** share a resizable panel beside the chart.
The panel starts closed. On a narrow host it opens as a full-size sheet with
keyboard focus and Escape handling. Use the panel's Close button to return to
the chart. Its width and selected view are saved in `WidgetState.panels`.
Older saved layouts without this field still load.

```ts
widget.openDataWindow();
widget.openObjects();
```

Data shows the hovered candle's OHLC, volume, available open interest, and named
study readings. Linked crosshairs update it too; leaving the chart returns to the
latest candle. Missing readings say **Unavailable**, while actual zero stays zero.
Shifted studies report the value drawn at that candle. The timestamp uses the
chart's timezone. Text can be selected and copied.

Objects groups rows by pane, each pane listed in draw order from back to front.
Drag a row onto the upper half of another to put it under that row, or onto the
lower half to put it over it; a drop the chart cannot paint is refused before it
lands. **Earlier** and **Later** step through the same order, so a drawing can sit
behind the series, between two studies or in front, and the price source can move
over a study. Move a study using its pane selector; its instance ID and alert
references remain intact. Select drawings and create a named group to show, hide,
lock, or remove them together. See [Objects](/docs/objects#draw-order).

Set `panels: false` to retain the standalone Objects popup and omit Data from
the toolbar. This affects the widget chrome only.

From 2.5.5, the same panel can also hold a **Watchlist** and a **News** reader when
you pass `watchlist: { store, quotes }` and `news: { feed }`. Each appears only when
its source is supplied; `widget.openWatchlist()` and `widget.openNews()` open them.
See [Watchlists & News](/docs/watchlists-and-news).

## Symbol search and direct typing

`symbolSearch(query)` remains a host-supplied lookup. Existing results with
`symbol`, `exchange`, and `name` still work. Add `assetClass` to expose category
filters, `iconUrl` for a symbol image, and `contractGroup` for an explicit list of
futures contracts. A contract's symbol and exchange come from your lookup; the
widget does not infer them from a ticker string.

```ts
const widget = createWidget(container, {
  symbolSearch: async query => searchInstruments(query),
});
// Example result from searchInstruments:
const match = {
  symbol: 'NOVA FUT', exchange: 'DEMO', name: 'Nova futures', assetClass: 'Futures',
  contractGroup: { label: 'Contracts', contracts: [
    { symbol: 'NOVA26SEP', exchange: 'DEMO', name: 'September 2026' },
    { symbol: 'NOVA26OCT', exchange: 'DEMO', name: 'October 2026' },
  ] },
};
```

Images accept HTTPS URLs or root-relative host assets. On a site hosted below a
path prefix, include that prefix in the image URL. Late search results are ignored
after the query, chart context, or mounted control changes.

Focus the chart and type an unassigned letter to search symbols, or a digit to
enter a timeframe. `15` means 15 minutes; explicit tokens such as `1h` work too.
Existing shortcuts, text editors, modifier keys, drawing placement, and open
dialogs retain their own keyboard handling. Set `typingNavigation: false` if your
host already owns direct typing.

## Study instances and colour controls

The Indicators picker lists **Running studies** separately from the catalogue.
Remove a specific running instance without removing another copy of that study.

A study your host protects with a [policy](/docs/indicators#study-policies) shows
only what the policy allows: its legend has no close button or gear, its Objects row
no remove, settings, move or reordering, and the right-click menu rows and the
picker's remove button are greyed with the note **protected**. Its settings dialog
declines with the reason, and a dialog already open when the host locks the study
reports each refused change instead of counting it, then closes on Cancel with the
same note. An unlisted study is left out of Objects, the picker's running list and
the alert source lists. Hiding it stays available.
Colour controls share a compact palette, recent colours, and a native custom
colour chooser. Values with alpha retain it; opacity is editable for those values.
Unsupported colour expressions remain unchanged until the user selects a colour.

Custom study descriptors can also declare symbol, session, multiline, price and
absolute timestamp inputs. Symbol lookup uses the configured `symbolSearch`
and commits its exchange with the instrument. Invalid drafts stay in the form
with an error. Price and time picking suspend the dialog and resume it after
selection or Escape; ambiguous study scales require an explicit pick target.
Timestamps are edited as UTC seconds without rounding fractional values.
See [typed study inputs](/docs/indicators#typed-study-inputs).

Unreleased: inputs can also be shown or enabled by another setting, and related
inputs can share one row. The dialog re-reads those rules on every edit and
announces what changed; see
[conditional inputs](/docs/indicators#conditional-inputs-and-inline-rows).

## Use individual controls in your own host

`AlertUi.context` exposes the same widget context used by its alert dialogs.
Custom terminals can also supply their own `WidgetContext` and compose controls:

- `readDataWindow(chart, time?, options?)` returns a snapshot without mounting DOM.
- `mountDataWindow(context, container)` mounts selectable readings; call `destroy()`
  when closing the panel.
- `createObjectsPanelContent(context)` returns content without popup furniture.
- `mountPanelDock(context, stage, options)` mounts one Data or Objects view at a
  time. Each content factory receives its container and returns a `destroy()` handle.
- `mountSymbolPicker(context, input, options)` supplies shared search results.
- `mountIndicatorInputControls(context, options)` adds search and picking to an
  existing study form. Supply the instance, input declarations, panel, field
  lookup and atomic `onPatch` callback. Destroy the returned handle with the form.
  A custom host can supply `suspend()` to release its modal during a chart pick.
- `mountQuickEntry(context, options)` uses the host's `enabled()` callback to decide
  which chart owns typing. Destroy it with the chart.
- `createColorPicker(document, options)` supports `openOverlay: context.openOverlay`
  so its palette stays above scrolling dialogs. Dispose it on unmount. For generated
  forms, pass the same opener to `renderForm` and call the returned `destroy()`.
- `renderForm(host, controlsFromInputs(inputs), options)` honours each input's
  `visibleWhen`, `activeWhen` and `inline` (unreleased). It asks `options.unavailable`
  again after every edit and every `sync`, so a host reason can depend on values;
  that reason wins over the condition's. After a sync that disables a field, call
  `refresh()` on the `mountIndicatorInputControls` handle so its pick follows.
- `inputStates(inputs, values)` returns each input's `{ visible, active, dependsOn }`
  and `inputConditionMet(condition, values)` tests one condition (unreleased), for a
  form of your own that must agree with the widget's.

When styles are supplied by the host, include `WIDGET_CSS` and
`WIDGET_COMPONENT_CSS`, then apply widget theme tokens. `createWidget` and
`createAlertUi` include these component styles automatically, including when an
alert-only host mounts before the first complete widget.

## Translations and host storage

Pass `translate` to `createWidget` or `createAlertUi` to translate desktop/mobile
controls, dialogs, tooltips, accessible names and widget feedback. `locale` remains
the separate number-formatting setting. English is the default.

```ts
import { createWidget, type WidgetMessageKey } from 'openalgo-charts/widget';

const messages: Partial<Record<WidgetMessageKey, string>> = {
  'Chart settings': 'Configuracion del grafico',
  'Close': 'Cerrar',
  'Interval {code}': 'Intervalo {code}',
  'schema.settings.tab.appearance': 'Apariencia',
};
const widget = createWidget(container, {
  locale: 'es-ES', translate: key => messages[key],
});
```

`WidgetTranslator` receives `(key, fallback, values)`. Return a template with the
same named parameters; the widget interpolates their literal values once and
renders plain text. Missing, blank, malformed or throwing translations fall back
to English. `widgetText` exposes this resolver for custom panels, with typed
parameters through `WidgetMessageParameters`. Generated field labels use
`schema.settings.<fieldKey>.label`, `schema.indicator.<id>.<key>.label`,
`schema.drawing.<toolId>.<path>.label` and `schema.alert.<key>.label`.

Symbols, exchanges, interval codes, values, user alert/drawing text, search result
names, object names, configured branding and engine/provider diagnostics remain
literal. Canvas labels stay under the engine's formatting contracts. A translator
belongs to its widget; recreate the widget for a complete language change.

For asynchronous account storage use `WorkspaceRepository` and `WorkspaceStorage`
from `openalgo-charts/workspace`. Failed writes reject and can be retried. Create
a new repository when the account namespace changes, and fence stale restores in
the host. `migrateWidgetWorkspace` imports validated legacy widget state. The
widget's `persist` convenience remains synchronous local preference storage.
Portable documents contain no credentials or trading account state.

Order-entry hosts can also pass `tradingCapabilities`, `tradingMode` and
`tradingLocked`. Unsupported routes are hidden; replay and host selection locks
disable placement. The menu rechecks current capabilities and chart context when
clicked. The existing `onOrder` callback remains the execution boundary.

## Install

```bash
npm install openalgo-charts
```

The widget entry imports `openalgo-charts` and `openalgo-charts/draw` itself. The
indicator picker offers whatever the indicator registry holds, so import
`openalgo-charts/indicators` alongside it for the 105 built-ins; without that import the
picker offers only what you registered yourself.

## One call

The widget uses 8 CSS pixels per bar by default, preserving candle density across
desktop and mobile. Set `navigation.defaultBarSpacing` to change this preference.
Use `navigation: { mousePan: 'both', defaultVisibleBars: 100 }` to show the
latest 100 bars on load and reset. Axes settings save these choices in the
widget layout. The count changes the visible window without discarding history;
0 fits all loaded bars. Mouse and pen pan time and price by default.
Choose `mousePan: 'horizontal'` for time-only panning. Saved preferences are retained.
Wheel input is proportional across pixel, line and page delta modes. Horizontal and
Shift-wheel input pan time, wheel input over a visible price axis scales that axis at
the pointer, and Ctrl-wheel or Meta-wheel pinch input zooms time at the pointer. See
[Interactions](/docs/interactions).

```ts
import { createWidget } from 'openalgo-charts/widget';
import 'openalgo-charts/indicators';
import { OpenAlgoDataFeed } from 'openalgo-charts';

const widget = createWidget('#terminal', {
  feed: new OpenAlgoDataFeed({ baseUrl: 'http://127.0.0.1:5000', apiKey: 'YOUR_KEY' }),
  symbol: 'RELIANCE',
  exchange: 'NSE',
  interval: '5m',
  theme: 'dark',
  persist: true,
});
```

The container is an element, a CSS selector or an element id, and it needs a non-zero
size before the call, the same rule `createChart` has. What comes back is a `Widget`:

```ts
widget.dataController;        // DataLoadingController | null (null without a feed)
widget.chart;                 // the Chart underneath, every base API available
widget.draw;                  // the DrawingController the rail drives
widget.objects;               // shared ChartObjects inventory and supported actions
widget.history;               // one undo timeline: studies, panes, scales, chart type, drawings
widget.series;                // primary handle, retained across chart-type changes
widget.root;                  // the .oac-widget element
widget.context;               // what every dialog was handed, for a panel of your own
widget.symbol(); widget.exchange(); widget.interval(); widget.chartType(); widget.theme();
widget.setSymbol('INFY', 'NSE');
widget.setInterval('15m');    // throws UnknownIntervalError for a code the registry lacks
widget.variant();             // the data variant in use, undefined for the feed's default series
widget.setDataVariant({ session: 'extended' }); // another provider series: a new source, reloaded
widget.setChartType('area');
widget.setTheme('light');
widget.openSettings();        // false when no settings dialog is registered
widget.openIndicatorPicker();
widget.openObjects();         // searchable inventory, false after destruction
await widget.reload();        // fetch again for the current symbol and interval
const saved = widget.getState();   // { version, symbol, exchange, interval, chartType, theme, variant?, chart, rail }
widget.restoreState(saved);        // { applied, reason?, chart? }
widget.destroy();                  // saves if persisting, removes the chrome, destroys the chart
widget.isDestroyed;
```

`restoreState` applies a saved viewport only when the state was captured on the same
symbol and interval; on any other dataset the indicators, drawings and panes still land
and the view is dropped, because a range of bar indices means nothing on different bars.
A restored layout starts a new undo timeline.

Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z, the rail's Undo and Redo and the mobile sheets all walk
`widget.history`: a study added or removed, its settings, the chart type, price scale
settings, pane moves, folds and heights, and drawings, in the order they were made. The
settings dialogs are one step per session, and a Cancel leaves none; a context-menu row is
one step. Undo never writes bars, fires an alert or places an order. A change your own code
makes that should not be a step goes through `widget.history.ignore(fn)`. See
[Undo and Redo](/docs/undo-history).
symbol, interval and [data variant](/docs/data-variants); on any other dataset the
indicators, drawings and panes still land and the view is dropped, because a range of bar
indices means nothing on different bars. A state without `variant` was saved on the
feed's default series (so was every state saved before variants existed), and it restores
onto the default series whatever the widget shows at the time; one this build cannot read
is refused before anything is applied.

A `Widget` is a thin owner. Anything the chrome does not expose, do on `widget.chart` or
`widget.draw` directly; the chrome observes the chart and stays in step.

The [Objects panel](/docs/objects) follows drawing selection and indicator changes,
offers only supported actions, and reuses the existing settings editors. The primary
price source is protected from removal. Register host-owned profiles explicitly on
`widget.objects`; arbitrary primitives and broker order lines are not inventory rows.

Dialogs respond to the actual widget container. At narrow widths the tab rail becomes
a horizontal tab list, fields fit the available width and actions remain reachable
while the body scrolls. This also applies to a small chart inside a wide desktop page.

## Mobile widget controls

The `mobile` option defaults to `'auto'`: compact controls activate when the widget
container is at most 640 CSS px wide or its primary pointer is coarse. This keeps the
controls on a phone in landscape. Use `'always'` for a permanently touch-oriented host
or `'never'` to keep desktop chrome at every width.

```ts
const widget = createWidget('#terminal', {
  mobile: 'auto',
  rail: { tools: ['trend-line', 'horizontal-line', 'rectangle'] },
});
```

The mobile header contains symbol entry and interval selection. Its bottom bar exposes
Draw, Studies, Objects and More according to the same `topbar`, `rail` and `indicators`
switches as desktop chrome. Drawing selection adds Properties, Lock or Unlock, and Delete.
The Drawing sheet includes Finish, Cancel, Undo, Redo, Magnet and Stay while a tool is
active, and the More sheet opens with Undo and Redo, disabled when there is nothing to take
back. `rail.tools` restricts both layouts to the same allowed drawing ids.

Both layouts drive one `DrawingController`, `ChartObjects` inventory, overlay stack,
selection and chart-wide undo history. A container resize changes the controls without replacing
the chart or its drawings. The widget also honors `prefers-reduced-motion: reduce`: when
the host omits `animZoom` or `animAutoscale`, their defaults become false. Explicit values
remain authoritative.

`mountMobile(ctx, options)` is exported for a host composing the widget pieces itself.
It returns a `MobileHandle` with `el`, `active()`, `refresh()` and `destroy()`. The widget
entry exports `MobileMode`, `MobileOptions` and `MobileHandle` as types. `createWidget`
is the usual entry because it supplies the shared context and teardown. See
[Mobile and Touch](/docs/mobile) and
[Scales and Panes](/docs/scales-and-panes#navigation-and-autoscale-animation).

## Options

Since 2.1.9, the widget inherits default corner branding
and an optional background watermark. `branding: false` disables the corner logo;
`watermark: true` enables symbol/interval text, which starts off otherwise. Use
Appearance in Chart settings for text, color, size and opacity. Symbol changes
update automatic text through the existing chart data context. See
[Branding and Watermarks](/docs/branding-and-watermarks).

`WidgetOptions` is `ChartOptions` plus the fields below. Every `ChartOptions` key
(`timezone`, `grid`, `priceScale`, `axisChrome`, `renderer`, `animZoom`, `animAutoscale` and the rest)
passes through to `createChart` unchanged.

| Option | Type | What it does |
|---|---|---|
| `feed` | `DataFeed` | Where bars come from. The widget calls `getBars` for the current symbol and interval (and `subscribeBars` when the feed has it), and again on every `setSymbol` / `setInterval` / `reload`; with no feed, put data on `widget.series` yourself. See [Custom Data Feeds](/docs/data-feeds). |
| `loading` | `DataLoadingOptions` | Shared-controller request timeout, page size/window, retained bar limit, optional polling and clock. |
| `symbol` | `string` | The instrument shown at start and in the top bar. Upper-cased. |
| `exchange` | `string` | Passed to the feed with the symbol. Default `''`. |
| `interval` | `string` | An interval code the interval registry knows (`'1m'`, `'5m'`, `'1d'`, or one you registered with `registerInterval`). An unknown code throws `UnknownIntervalError`; a persisted code this build does not know falls back to `'1d'`. Default `'1d'`. |
| `intervals` | `string[]` | The interval pills. Default: `DEFAULT_INTERVALS` (`1m 5m 15m 1h 1d 1w`) plus every other registered code. |
| `variant` | `DataVariant` | Which of the feed's series to show: `{ session: 'extended' }`, `{ adjustment: 'raw' }`, a currency or a unit. The feed must declare it through `dataVariants`, or the chart shows "Not available from this source" with no retry. A malformed one throws a `TypeError`. | `theme` | `'dark'` \| `'light'` \| `ChartTheme` | A named palette or a full theme object. Drives both the canvas and the chrome tokens (see below). Default `'dark'` (the engine's own default is light). |
| `rail` | `boolean` \| `RailOptions` | The drawing rail. `false` hides it; `tools` restricts which registered tool ids appear (the order follows the rail's own groups); `favorites` seeds the pins when nothing is stored. |
| `topbar` | `boolean` | The symbol, interval, chart type, indicators, capture, settings and theme controls. |
| `statusline` | `boolean` | The status line under the chart. |
| `mobile` | `'auto'` \| `'always'` \| `'never'` | Responsive widget controls. Default `'auto'`, active at a container width of 640 CSS px or less or when the primary pointer is coarse. |
| `indicators` | `boolean` | The Indicators button and picker. Turn it off for a host that manages indicators itself. |
| `persist` | `boolean` \| `string` | `true` saves the state under the `default` namespace (`oac-widget:default:state`) and restores it on the next `createWidget`; a string names the namespace, for more than one widget per origin. |
| `storage` | `StorageLike` \| `null` | The store behind `persist`. Default: the page's `localStorage`. |
| `locale` | `string` | A BCP 47 tag the status line formats numbers with. |
| `symbolSearch` | `(query) => SymbolMatch[] \| Promise<SymbolMatch[]>` | Called as the user types in the symbol box; the results open as a menu under it. |
| `lookbackBars` | `number` | Bars per load. Default 500. |
| `now` | `() => number` | The clock for the load window and the capture filename. Default `Date.now`. |
| `onOrder` | `(order: OrderRequest) => void` | Order entry from the right-click menu (`{ side, type, price, paneIndex }`). `price` is the pointer's price, not snapped to the instrument's tick or tick schedule: round it, for example with `validatePrice`, before sending. Without it the menu draws no trade rows. Limit and stop rows appear only over the price pane, where the pointer's price is the instrument's; a study pane offers the market rows alone. |
| `movablePrimaryPane` | `boolean` | Off by default, as in the engine. Pass `true` to let a trader move the price pane below the studies; all of the widget's chrome follows it. | `account` | `AccountStateSource` | The selected account's equity and margin in the status line, with a menu to switch account, usually a trade-tier `AccountManager`. A source whose provider declares no accounts shows disabled with the reason; omitted shows nothing. It reads and switches accounts only. See [Accounts and advanced orders](/docs/trading-accounts). |
| `styleNonce` | `string` | The host's CSP nonce for the shared widget and dialog stylesheet. See [Content Security Policy](#content-security-policy). |

The chrome switches (`rail`, `topbar`, `statusline`, `indicators`) default to on, so a
bare `createWidget(el)` is the full terminal. `persist` defaults to off: nothing is
written to storage until you ask.

<Callout type="info">
A control exists only where the engine has something behind it. Every dialog is generated
from a schema the engine already ships: chart settings from `chartSettingsSchema`,
indicator settings from the descriptor, drawing properties from `drawingSettingsSchema`,
so a field appears only when the renderer reads it. The right-click menu draws its order
rows only when `onOrder` is given, offers **Move pane up** and **Move pane down** over any
pane when there are two or more, the price pane included (greyed at the top or bottom, and
greyed with a note on a widget built without `movablePrimaryPane`, where the price pane
stays on top), and offers **Collapse pane** or **Expand pane** only over a study pane, since
the price pane always stays open in whatever slot it sits. Moving the price pane below its
studies is saved with the layout and reported as a `layout` event with reason `paneMoved`.
The Objects panel names it **Price pane** in its headings and move targets, wherever it sits.
</Callout>

## Live history and reconnect recovery

After loading history, the widget passes its last bar as `seedFrom` in the optional
third `subscribeBars` argument. A compatible live feed can continue the forming candle
and call `onResync` if a restored connection may have missed data.

On `onResync`, the widget pauses display updates, buffers incoming live bars, and requests
the current history window with `noCache: true`. It merges those observations into the
refreshed history, replaces the series, preserves the visible logical range, and seeds
the next subscription from the merged last bar. Monitoring continues during the fetch;
another reconnect starts a newer request and supersedes the earlier one.
`withBarCache` honors the bypass; custom cache wrappers should forward or honor it too.
Responses and live callbacks from a superseded symbol or interval are ignored.

At matching timestamps, the merge keeps the history open, combines high/low extremes,
uses the latest buffered close, and takes the maximum volume instead of adding two
snapshots. This repairs the available bars; it does not replay unseen trades.
Bars without buffered updates retain the authoritative history values. The overlap
merge is conservative: a buffered candle can retain a seed extreme that history has
corrected. Exact snapshot/tick reconciliation requires a host-specific protocol.

If this automatic refresh fails or returns no bars, the previous chart remains visible,
the status line reports stale history, and a `data` event carries the error. Display
updates stay paused while live buffering and reconnect monitoring continue. Call
`widget.reload()` to retry; the cache bypass remains active until a load succeeds.
Manual reload keeps its usual fit-to-data behavior, subject to restoring a saved view;
viewport preservation is specific to automatic reconnect recovery.

## Events

```ts
widget.on('symbol', (e) => console.log(e));    // { symbol, exchange }: picked in the top bar, or setSymbol
widget.on('interval', (e) => console.log(e));  // { interval }
widget.on('variant', (e) => console.log(e));   // { variant? }: setDataVariant or a restored state
widget.on('theme', (e) => console.log(e));     // { theme, chartTheme }
widget.on('layout', (e) => console.log(e));    // { reason, chartType? }: getState() would now return differently
widget.on('data', (e) => console.log(e));      // { symbol, interval, bars, error? }: a load finished or failed
widget.on('status', (e) => console.log(e));    // { text, kind }: the status line's message changed
```

`on` returns the unsubscriber; `off(event, cb?)` is the same thing by name. The seven
events are what a host needs to keep its own state (a URL, a workspace, a watchlist) in
step with the chrome. Everything the chart itself emits (`crosshair:move`, `contextmenu`,
`trading:*`, the drawing controller's `drawing:*`) is still there on `widget.chart` and
`widget.draw`; see [Events](/docs/events). The exact callback payloads are in
`dist/widget/index.d.ts`.

## Theming tokens

The chrome never carries a colour of its own. `widgetTokens(theme)` derives every chrome
colour from the active `ChartTheme`: panels are the theme `background` stepped towards
white or black, borders come from `axisLine` and `paneSeparator`, text from `axisText`
lifted for legibility, the accent from `lineColor`, and the buy and sell colours from
`upColor` and `downColor`. Spacing, radius and font are added, and the set is written as
`--oac-` custom properties on the widget root, `.oac-widget`. One `<style>` element is
injected per page, scoped under that class, so nothing leaks into the host page and
nothing from the host page leaks in. Calling `setTheme` rewrites the tokens; every control
follows without a repaint of its own.

| Token group | Names (each prefixed `--oac-`) |
|---|---|
| Surfaces | `bg`, `panel`, `panel-2`, `elev`, `elev-2`, `elev-3`, `scrim`, `shadow` |
| Borders | `bd`, `bd-soft`, `bd-hover` |
| Text | `tx`, `tx-strong`, `mut`, `faint` |
| Accent and state | `acc`, `acc-2`, `on-bg`, `on-bd`, `ring`, `ring-soft`, `buy`, `sell`, `amber`, `danger` |
| Scrollbars | `sb-thumb`, `sb-thumb-hover` |
| Type and metrics | `font`, `mono`, `fs`, `radius`, `rail-w`, `topbar-h`, `status-h`, `ctl-h` |

The tokens are set as inline custom properties on the root (that is how `setTheme` can
swap them without touching the stylesheet), so a host override in a stylesheet has to
outrank an inline declaration:

```css
#terminal .oac-widget {
  --oac-font: "IBM Plex Sans", system-ui, sans-serif !important;
  --oac-radius: 4px !important;
}
```

Text, number, select and date fields share the form's control column. Fields and
buttons use `--oac-ctl-h` for height and `--oac-radius` for their outer corners;
color swatches stay compact. Select chevrons stay inside their control.

Override tokens, not controls: a rule written against an internal class name is a rule
against an implementation detail.

## Content Security Policy

Pass the nonce generated by your server for this response through `styleNonce`:

```ts
createWidget('#terminal', { styleNonce: requestNonce });
```

The widget assigns the style element's `.nonce` before adding its CSS to the document.
The shell and dialogs share one stylesheet, including when multiple widgets use the
same document. The lower-level helper accepts the same value as
`injectWidgetStyles(document, extraCSS, requestNonce)`.

A matching stylesheet policy can be paired with a separate style-attribute policy:

```http
Content-Security-Policy: style-src-elem 'nonce-RESPONSE_NONCE'; style-src-attr 'unsafe-inline'
```

`RESPONSE_NONCE` is a placeholder for the same fresh, unpredictable response nonce
passed to the widget. This example covers style directives; the host manages the rest
of its CSP. A stylesheet nonce does not authorize inline style attributes. The widget
uses dynamic inline styles for theme tokens and layout, so assess the attribute policy
separately.

For server-rendered markup, an empty `<style id="oac-widget-css" nonce="...">` is filled
in place, retaining its nonce. Include the nonce in the HTML itself: an empty style
element without one can trigger a CSP report during parsing, before the widget runs.
A populated stylesheet with this id is left untouched, including its CSS and nonce;
a host supplying the full stylesheet must include both `WIDGET_CSS` and `DIALOG_CSS`.

## Extending the rail with your own tools

The rail is a view of the draw tier's tool registry. Register a tool the way
[Drawing Tools](/docs/drawing-tools#building-your-own-tool) documents, then name it in
`rail.tools`:

```ts
import { createWidget } from 'openalgo-charts/widget';
import { registerDrawingTool, LINE_FIELDS, type DrawingTool } from 'openalgo-charts/draw';

const midline: DrawingTool = {
  id: 'midline',
  name: 'Midline',
  points: 2,
  angleLock: true,
  shortcut: 'Alt+M',
  settings: LINE_FIELDS,
  draw(c) {
    // paint a horizontal line at the midpoint of the two anchors
  },
  distance(x, y, c) {
    // media px from the cursor to the line, or null for a miss
    return null;
  },
};
registerDrawingTool(midline);

createWidget('#terminal', {
  rail: { tools: ['trend-line', 'horizontal-line', 'midline', 'fib-retracement'], favorites: ['midline'] },
});
```

Register before you call `createWidget`: the rail reads the registry once when it builds,
shows only ids it finds there, and drops a favourite it cannot resolve. The rail labels
every button with the tool's `name` and draws a glyph when the draw tier's icon registry
(`DRAWING_TOOL_ICONS`) has one for the id. A tool that declares
`shortcut` is bound by the widget's keymap and listed in the `?` panel, and a binding that
collides with an existing one is reported rather than silently overridden. `settings`
decides what the drawing properties dialog shows for the tool: a control appears only for
a field the tool's `draw` reads.

## Loading without a bundler

Every tier bundle imports its neighbours by sibling path (`./openalgo-charts.mjs`,
`./openalgo-charts.draw.mjs`), so `dist/` served as-is is enough and no import map is
needed:

```html
<div id="terminal" style="height: 600px"></div>
<script type="module">
  import { createWidget } from '/dist/openalgo-charts.widget.mjs';
  import '/dist/openalgo-charts.indicators.mjs';
  createWidget(document.getElementById('terminal'), { symbol: 'RELIANCE', interval: '5m' });
</script>
```

The standalone script (`openalgo-charts.standalone.js`) is base-only and cannot host the
widget: a tier loaded beside it would import its own second engine. See
[Use from a CDN](/docs/cdn).

## In a framework

Create the widget in a mount effect, hold it in a ref, and `destroy()` it on cleanup, the
same lifecycle as a bare chart in [Framework Integration](/docs/frameworks). The widget
instance is never framework state: it owns DOM of its own and re-rendering around it is
wasted work.

## Managed loading (2.1.6)

With a feed, `widget.dataController` owns history, streaming and older pages.
The widget shows compact accessible loading, empty, refreshing, stale, error and
Retry states, including failures in external studies. Retention limits are
reported separately from provider exhaustion. Controls work with topbar or
statusline hidden and inherit the widget theme and stylesheet nonce.

`widget.reload()` refreshes the same instrument while retaining its time anchor.
Symbol and interval changes clear the old primary data, set `ChartDataContext`,
and reject obsolete responses. Saved view restoration belongs to the instrument
on which it was captured. The history loader always releases its completion latch.
For a custom replay host, call `dataController.setPaused(true)` for the entire
replay lifetime, including paused replay; stop replay before resuming delivery.
See [data loading](/docs/data-loading) for the interactive failure/retry example.

## Go to a date or range

**Go to** in the toolbar (or **More**, then **Go to** on a narrow screen) opens a
compact panel. **Date** shows one date at the current zoom; **Range** fits two
dates, or two date and time pairs, to the plot. Dates and times are read in the
chart timezone, IST unless the host sets another. A blank time is the start of
the day, or its end for the To field. Daily and longer intervals show the date
fields alone, since a time cannot change which bar a date names. On a tick or
volume interval the button is greyed with the reason, and
`widget.openDateNavigation()` returns false.

When the date is older than the loaded history, the widget pages back through
its feed first: a date-window feed receives one request that reaches the date,
a paged feed one page at a time. The view moves only after that load is
accepted, so later live bars and refreshes keep the placement instead of
returning to the newest bars. Closing the panel while it is loading cancels the
request: the older bars still arrive, but the view stays where the user left it.
A pan or zoom while older history loads does the same, from a gesture, a key, a
linked chart or the host's own `setVisibleLogicalRange`; the move the widget makes
itself to keep the bars in view still when a refresh lands does not count. The
panel closes when the interval or the chart timezone changes under it, since its
fields were built for both.

```ts
const result = await widget.goTo({
  from: zonedStringToUtcSeconds('2024-03-04', widget.chart.timezone()),
  to: zonedStringToUtcSeconds('2024-03-28 23:59', widget.chart.timezone()),
});
// { status: 'placed', from, to }  open times of the first and last placed bars
```

| `status` | Meaning |
| --- | --- |
| `placed` | The date or range is in view. |
| `partial` | Something is in view, but `history` says why the source stopped before the requested start (`exhausted`, `empty`, `limited` or `unavailable`), or `clipped` says the range is wider than the plot and its start is shown. |
| `no-data` | No bar at or after the date, or none inside the range. The view is unchanged. |
| `unsupported` | The interval has no time buckets (tick or volume bars). |
| `invalid` | A non-finite time, or a range that ends before it starts. |
| `cancelled` | A newer request, a symbol or interval change, a pan or zoom while older history loads, or `destroy` took over. |
| `error` | The feed failed; `error` carries the reason. |

A date lands on its own daily bar whether the feed stamps bars at midnight or at
the session open, and on a day of 23 or 25 hours around a daylight saving change.
It names the bar the axis labels with that date: west of UTC, a daily bar stamped
at UTC midnight is labelled with the previous date and is found by it, so set the
chart timezone to `UTC` for such a feed when its bars should read by their UTC
date. A date on a weekend or in an overnight gap moves to the next
session. History is never loaded during replay, and a date beyond the replay
cursor is `no-data`. A chart linked through a link group follows the placement
by time. The panel closes once a request is placed and otherwise keeps the reason
in view. `widget.openDateNavigation()` opens it programmatically. A custom host
uses the same rules through `DateNavigator` and `openDateNavigation`, whose
`cancel` option runs when the panel is dismissed mid-load and whose `pending`
option lets a host that rebuilds its chart reopen the panel on a request already
under way; see [data loading](/docs/data-loading). Only the host knows which view
moves are its own, so a custom host that wants a pan or zoom to drop a loading
request listens for the chart's `pan` and `zoom` events around its loader and
calls `navigator.cancel()`.

## Timeline event details

For grouped timeline events, the widget opens an accessible text-only details
popup when a marker or cluster is selected. Populate `widget.chart.setEvents(...)`
and optionally `setEventGroups(...)`; the package supplies no calendar feed.
`eventDetails: false` disables the popup. An `eventDetails.loadDetails` callback
can retrieve additional host-owned data; its abort signal and stale-result guards
prevent an old request from replacing a newer selection. The popup closes on
Escape, context changes and event replacement. See [Events](/docs/events).

## Trader alerts

For the standalone base controller, delivery events and restore order, see
[Trader Alerts](/docs/alerts). This section covers the widget editor and list.

The widget owns `widget.alerts`, an `AlertController` attached to its chart and
drawing controller. Open **Alerts** in the desktop toolbar, or **More**, then **Alerts**
on a narrow screen. `widget.openAlerts()` opens the same list programmatically.
Do not create a second controller on a widget chart.

The editor offers price thresholds, a specific study instance and plot, supported
drawing levels, and registered candle conditions. Drawing alerts on study panes
require a plot from that pane. Missing plot values remain unavailable; they do
not become zero. A zero threshold is valid.

**Bar close** is the default: the next live bar confirms the previous one.
**Intrabar touch** can fire on a wick absent from the final candle, so the editor
states that tradeoff beside the controls. Crossing conditions require movement
beyond the threshold; equality alone is not a crossing. Range boundaries count
as inside. Cooldown uses seconds. Expiry uses the chart timezone shown beside
the field when the editor opens. That timezone stays fixed for the draft even
if the host changes the chart's timezone. New drafts start two calendar months
ahead, clamped to the target month's last day. Clear the field for no expiry.
Existing alerts keep their expiry, including seconds, when other fields change.
Stored `expiresAt` values remain UTC epoch seconds.

Save commits the draft; Cancel and Escape discard it. Editing a triggered alert
preserves that state unless Enabled is explicitly changed. The list retains
armed, disabled, expired and triggered records, with their last delivery and any
availability reason. Right-click a price, study or supported drawing to seed an
editor from that target.

Armed price and study threshold lines can be dragged by their line or **Alert** badge.
Movement previews the new level; release commits the threshold once. Saved state
and evaluation keep the original threshold during the preview. Escape, touch
cancellation, a pinch, instrument-context changes, host pause and replay entry
cancel an unfinished drag. Paused alerts cannot be dragged; triggered, disabled
and expired levels are read-only until rearmed.

Each range boundary stops at the other boundary without moving it. Study levels
use the selected plot's axis and units, including an independent or left scale.
When a plot uses a different scale, its alert does not put that number on the
primary right axis; read the source value in the alert editor.
Drawing-owned levels remain attached to their drawing; move the drawing instead.
Try the [live alert-line demo](/examples#alert-threshold-dragging).

```ts
const widget = createWidget(container, {
  symbol: 'CONTRACT', exchange: 'DERIVATIVES', interval: '1m',
  persist: 'my-chart',
});
widget.alerts.add({
  source: { kind: 'price', price: 100 },
  condition: 'crossingUp', policy: 'onBarClose', title: 'Confirmed crossing',
});
widget.chart.on('alert:triggered', event => deliverFromHost(event));
```

The widget shows a toast for a trigger; external delivery remains the host's job.
With persistence enabled, alerts save in the chart state and restore after their
drawings and study identities. Reloading history sends no alerts. A triggered
once alert remains visible after reload. Invalid portable host payloads produce
a save-status error and do not prevent widget cleanup.

Custom hosts can mount `mountAlertEditor(ctx, anchor?, { source?, alertId? })` and
`mountAlertsPanel(ctx, anchor?)` from the widget entry. Both return a `PanelHandle`
and dispose their subscriptions when closed. `alertSettingsSchema` is available
from the base entry for hosts that provide their own forms.

For a custom chart host without a `WidgetContext`, `createAlertUi` provides the
shared dialogs over a positioned container:

```ts
import { AlertController } from 'openalgo-charts';
import { createAlertUi } from 'openalgo-charts/widget';

const alerts = new AlertController(chart, { drawings: draw });
const alertUi = createAlertUi(container, {
  chart, draw, alerts, theme: 'dark',
  onOpenChange: open => { hostShortcutsEnabled = !open; },
});
alertUi.openList();
// On teardown, the host owns all three lifecycles.
alertUi.destroy();
alerts.destroy();
draw.destroy();
```

The adapter owns only its dialogs. It does not load data, place orders, persist
records or send notifications. Use a container spanning the workspace so the
editor remains readable when its source chart is narrow. The yfinance reference
host demonstrates this integration on both charts and persists their alerts
with the surrounding chart documents.
