# Architecture

import ArchitectureDiagram from '../../components/ArchitectureDiagram'

OpenAlgo Charts 2.1.9 is a browser charting engine with no runtime dependencies.
Each pane has a base canvas for chart content and an overlay canvas for transient
interaction. You can build your own interface or use the optional widget tier.

## The layers

**Public API.** `createChart`, `addSeries`, `registerIndicator`, event subscriptions
and `takeScreenshot`. See [Core Concepts](/docs/core-concepts).

**Rendering.** An invalidation-aware render loop drives one base canvas and one
overlay canvas per pane, plus crosshair, axes, grid and [themes](/docs/themes).
Cursor-only work stays on the overlay canvas, and live updates are coalesced to
animation frames. The series pass on each pane goes through a render backend
port: the shipped Canvas2D backend is the default, the `openalgo-charts/webgl`
tier puts a WebGL2 backend behind the same port, and `exportSVG` runs the same
paint into a serialising context. See
[Render Backends & SVG Export](/docs/rendering). A source-bar update currently repaints base content across
active panes, so [Performance & Operations](/docs/performance-and-operations)
covers the retained-history and canvas-memory budgets for sustained sessions.

**Drawables.** [Chart types](/docs/chart-types), [indicators](/docs/indicators),
[drawing tools](/docs/drawing-tools) and [primitives](/docs/primitives-and-plugins).
Chart types, indicators and drawing tools use registries. Primitives extend the
chart through attachment, rendering, lifecycle and hit-test contracts.

**Shared model.** One [DataLayer](/docs/data-loading) merges every series onto a
gapless logical index, a single time scale is shared across panes, and each pane
owns its [price scale](/docs/scales-and-panes). [Transforms](/docs/transforms)
turn bars into Renko, Range, Point and Figure, Kagi, Line Break or Heikin Ashi.

**Session.** [Replay](/docs/market-replay), [comparison](/docs/symbol-comparison),
[chart linking](/docs/chart-linking), [keyboard shortcuts](/docs/keyboard-shortcuts)
and the [drawing controller](/docs/drawing-clipboard).

**Trade layer.** Order engine with a state machine and OCO, a depth-of-market
ladder with configurable tick grouping, and drag-to-modify. Grouping combines
display rows; it does not change valid order prices. See
[Order Engine & Ladder](/docs/trading) and the [depth demo](/docs/depth-of-market).

**Feeds and data.** A headless [shared loading controller](/docs/data-loading),
per-feed request scheduling, validated closed-bar cache snapshots, [REST history](/docs/live-data),
[live WebSocket data](/docs/live-data), the trading API, a candle builder that folds
ticks into OHLC, and full IANA [timezone](/docs/timezones) handling.

## Where calculations and rendering run

The browser receives data from host-provided adapters. The DataLayer, indicators,
transforms and profile calculations run in JavaScript on the CPU. The optional
WebGL2 backend uses the user's GPU to draw supported series, then composites them
into the pane's base canvas. It does not move indicator or profile calculations
to the GPU. Axes, text, drawings and profile primitives continue to use Canvas 2D.

The homepage's BTC/USD adapter and the simulated depth feed are website examples;
applications supply their own data connections. They are not bundled market-data
services. See [Custom Data Feeds](/docs/data-feeds).

## Bundle tiers

The base engine is what you always pay for. Everything else is a separate entry
point exposing that feature's APIs. Some tiers also register built-in indicators,
chart types, drawing tools or rendering backends when imported. Unused optional
tiers stay outside the base bundle.

| Tier | Brotli | Contents |
|---|--:|---|
| `openalgo-charts` | 76.16 KB | Engine, 13 chart types, panes and scales, primitives, registries, chart state, linking, bar cache, trading overlay, SVG export, render backend port, feeds |
| `openalgo-charts/widget` | 41.91 KB | Packaged interface controls through `createWidget`: top bar, drawing rail, mobile controls, status line, dialogs, right-click menu, keymap and persistence |
| `openalgo-charts/indicators` | 28.05 KB | 102 built-ins, shared TA helpers, and the Tier-2 external-data contract |
| `openalgo-charts/draw` | 25.90 KB | 51 drawing tools, headless controller, clipboard, settings schema |
| `openalgo-charts/profile` | 14.96 KB | Volume Profile, Market Profile (TPO), Footprint, order flow |
| `openalgo-charts/trade` | 7.61 KB | Order, position and bracket tools, DOM ladder |
| `openalgo-charts/webgl` | 6.38 KB | WebGL2 series backend, composited into the pane's canvas, 2D fallback for the session on context loss |
| `openalgo-charts/transform` | 2.66 KB | Heikin Ashi, Renko, Range, Line Break, Point and Figure, Kagi |

**203.62 KB Brotli** for every tier at once; a widget terminal (base + draw +
indicators + widget, what one `createWidget` call loads) is 172.02 KB. Figures are
the measured `size-limit` output and are enforced in CI, so a change that grows a
bundle past its budget fails the build.

The widget is a packaged host that drives the seven capability layers through the
same public API as your own interface. The base engine creates its canvas and
container elements; the widget adds the toolbar, dialogs and other interface
controls. See [The Widget Tier](/docs/widget).

## Custom indicators

The 102 built-ins are not special-cased. Each one is a descriptor: inputs, plots and
a `calc` function, optionally with `markers`, `draws`, `levels`, `background`,
`barColors`, `fills`, `alerts` and a `table`. Anything you register through
`registerIndicator` uses exactly the same contract and gets the same treatment,
including generated settings, legend entries and state persistence.

No fork, and no build step. See [Indicators](/docs/indicators) for the contract.
